## v1 → v2 변경 요약
- **C. 캐릭터 시스템** "비주얼 생성"·"이미지 생성 타이밍" 갱신: 알·균열 시퀀스를 AI 생성 → 고정 이미지(사용자 color_palette 적용)로 정정. AI 이미지 생성은 유아 단계부터 5장으로 축소.

## 0. 한 줄 요약

런닝 기록 스크린샷을 VLM으로 파싱해 다마고치형 캐릭터를 키우는 PWA. "같은 거리를 어떻게 뛰었는지"가 캐릭터 외형에 시각적으로 누적되는 것이 단순 트래커와의 핵심 차별점.

## 1. 기획 완료된 내용

### A. 정체성 / 컨셉
- 런닝 스크린샷 → VLM 파싱 → 다마고치 캐릭터 성장 PWA
- 차별점: "어떻게 뛰었는지가 외형에 시각적으로 누적"
- 핵심 루프 5단계
  1. 사용자가 런닝 앱 스크린샷(Strava/나이키런/삼성헬스 등) 업로드
  2. VLM이 거리/페이스/시간대/심박/루트 등 속성 파싱
  3. 속성이 캐릭터에 경험치 + 태그로 누적 (예: 야간런 → 月속성 태그)
  4. 최초 1회 생년월일로 사주 추출 → LLM이 동물 + 판타지 속성 부여한 "알" 생성
  5. 5/10레벨마다 누적 속성을 반영해 다음 단계 캐릭터 이미지로 진화

### B. 기술 스택
- **플랫폼**: PWA 우선 (웹/모바일 겸용). Next.js + PWA 가정. 네이티브 앱은 추후 확장.
- **AI 스택**: GPT API 통일. VLM(이미지 파싱) + LLM(사주→캐릭터 서사, 진화 비주얼 프롬프트) + 이미지 생성 모두 GPT 계열.
- **사주 깊이**: 오행 + 십신/일주까지 활용. 단순 오행 비율을 넘어 성격/일주 기반 캐릭터 서사 생성. 시주는 제외.
- **MVP 범위**: 전체 파이프라인 얇게 한 사이클 (업로드 → 파싱 → 경험치 → 진화)을 끝까지 구현해 사용자 테스트.

### C. 캐릭터 시스템
- **비주얼 생성**:
  - **알·균열 시퀀스 = 고정 이미지**. 알(baseline) + 균열 N단계 + 대균열 모두 공통 형태의 고정 일러스트. 사용자별 차이는 O2에서 선택한 `color_palette` 색상 적용뿐. AI 생성 없음.
  - **유아~완전체 5단계 = 매번 AI 이미지 생성**. 진화마다 새 이미지.
- **정체성 보존 4중 장치** (매번 AI 생성의 일관성 리스크 대응)
  1. **DNA 카드**: 사주 + 동물 + 판타지 속성을 텍스트로 영구 고정해 모든 프롬프트에 prepend
  2. **5단계 묘사 텍스트 사전 작성 (스토리보드)**: 캐릭터 생성 시점에 1~5단계 외형 묘사를 LLM이 한꺼번에. 진화 시 해당 단계 텍스트를 프롬프트에 사용. 성장 방향성이 처음부터 일관됨.
  3. **이전 단계 이미지를 레퍼런스로 입력** (GPT-4o image input). 진화 시 시각적 연속성 확보.
  4. **비주얼 슬롯 한정**: 이마/등/꼬리/색조/오라 등 부위 슬롯을 미리 정의, 누적 속성이 슬롯에만 들어감.
- **이미지 생성 타이밍 (평생 AI 생성 5장)**
  - 가입 직후: 알·균열 시퀀스 고정 이미지 사용 (AI 생성 X, color_palette만 적용) + 6단계(알 포함) 묘사 텍스트 사전 작성
  - **누적 10km 달성 시**: 부화 연출 (고정 균열 시퀀스 재생) + 유아 이미지 1장 신규 생성
  - **부화 이스터에그**: 부화 시점의 누적 거리 조건에 따라 캐릭터에 추가 signature_mark가 붙은 채 부화. 진화해도 영구 유지. 사용자에게 조건 비공개.
    - 정확히 10.0km 부화: 희귀 추가 마크 (예: 눈동자 속 별, 이마의 보석 등)
    - 한번에 넘김 (9km→11km+): 별도 추가 마크 (예: 불꽃 자국, 번개 무늬 등)
    - 20km 이상 부화: 상위 희귀 추가 마크
  - Lv.10/20/30/40 만점 자동 트리거: 유년·초기체·중기체·완전체 각 1장 신규 생성 (누적 속성 반영)
  - Lv.50 도달 = 완성. 외형 변화 종료, 칭호 시스템으로 정체성 확장. 완전체는 stage에 영구 잔류.
- **성장 단계**: 알(사전 단계, 레벨 없음) + 5단계 진화형(유아→유년→초기체→중기체→완전체). 진화형 각 10레벨씩 총 Lv.1~50.
- **알 → 캐릭터 확정**: 첫 가입 시 사주 기반 색상 3개로 알 3개 제시, 색상만 보고 1개 선택 (정보 비공개, 이름은 부화 후). Lv.50 도달 시 완전체는 stage에 영구 잔류하며 새 캐릭터와 공존. 사용자가 원할 때 "새 알" 버튼으로 새 사이클 시작 (강제 아님).
- **ART_STYLE_GUIDE 상수**: 앱 전체 이미지 생성 프롬프트에 동일 prefix로 삽입. soft painterly, pastel background, full body, slight 3/4 view, clean lineart, no text. 화풍 흔들림 방지.

### D. 사주 → 알 LLM 파이프라인 (가입 직후 1회, 30초~1분)
1. **사주 계산**: `lunar-typescript` (npm) 로컬 계산. 시주 없이 년·월·일주 + 오행/십신.
2. **DNA 카드 생성**: GPT-4o, `response_format: json_schema` 강제. 공개 필드(name·gender) + 내부 필드(archetype·fantasy_modifier·signature_marks·color_palette·lore_one_liner·element_base·element_balance·temperament). gender는 LLM이 아닌 서버에서 50% 확률 랜덤 부여 (`수컷`/`암컷`).
3. **6단계 묘사 텍스트 일괄 생성**: GPT-4o 호출 1회로 알·유아·유년·초기체·중기체·완전체 외형 묘사를 한 번에. 한 컨텍스트에서 만들어야 성장 방향성 일관됨.
4. **알 이미지 생성**: GPT 라인 최고 이미지 모델(현재 `gpt-image-1`). 신모델 나오면 교체. MVP는 품질 우선.

### E. 사주 비공개 원칙
- 사주는 100% 내부 시드. 사용자에게 일주·오행·temperament 등 사주 단어/필드를 절대 노출하지 않음.
- 캐릭터 공개 필드는 `name`(이름)·`gender`(성별) 2개뿐. archetype·fantasy_modifier·signature_marks·color_palette·lore_one_liner 등 나머지는 전부 내부 시드.
- S2 카피에서도 "운명/사주" 단어 사용 금지.

### F. 성장 공식
- **EXP 공식**: `EXP = (km × 10) + 빈도보너스 + 다양성보너스`
  - 빈도 = 연속일수·주간횟수 가중치
  - 다양성 = 새 시간대/거리/환경/강도/날씨 첫 등장 시 +20~50
- **일일 EXP 캡**: 600. 같은 날 2번째 기록부터 base EXP만 50% 지급(다양성 보너스는 정상).
- **레벨 곡선**: 누적 EXP 목표 약 500 / 1500 / 3500 / 7000 / 13000 (단계마다 1.5~2배).
- **진화 트리거**: Lv.10/20/30/40 만점 도달 시 백그라운드 자동 이미지 생성(4회). 완료 시 PWA 푸시 + 메인 진입 전면 모달. 생성 실패 시 즉시 사용자 알림 + 수동 재시도 버튼(E2).

### G. 정체성 확장 시스템
- **칭호**: PB·누적 거리·첫 우중런·연속 일수·시간대·환경 등 조건 만족 시 획득 (예: 마라토너, 밤의 수호자, 산악의 정복자). 장착 없음 — 수집·기록 전용. P1 프로필에서 획득 기록 열람. 완전체 도달 이후에도 정체성 확장 장치로 작동.

### H. 부정 방지 (3-게이트)
- **Gate A 자동 차단**: 이미지 SHA-256 해시 중복만 차단 (EXIF/AI 탐지는 MVP 제외).
- **Gate B 자동 거부**: 페이스 ≤ 2:50/km, 수치 자기모순(거리·시간·페이스 ±5% 불일치), 거리>100km & 시간<5h, 시작시각 미래.
- **Gate C 사용자 확인**: 평소 평균 페이스 대비 ±20% 이탈, 24h 누적>42km, 같은 날 3건 이상, 시간 구간 겹침. "맞아요" 확인 후에만 다양성 보너스·PB 지급.
- **업로드 후 수정·삭제 불가**: S6 [확정] 버튼이 최종. 도핑 차단 목적.

### I. 온보딩 / 계정
- **소셜 로그인 3종**: Google · Kakao · Naver. Apple 제외 (생년월일 제공 불가).
- **생년월일 수집**: 소셜 로그인 동의 항목으로 자동 수집 시도 (구글 `people.birthdays.read` / 카카오 `birthyear`+`birthday` / 네이버 `birthyear`+`birthday`). 못 받으면 한 줄 입력 fallback.
- **안 받는 정보**: 태어난 시간, 성별. (사주 시주 제외와 맥 일치)

### J. 런닝 기록 입력
- 스크린샷 업로드 + VLM 파싱값 수동 보정 가능.
- Strava API 등 직접 연동은 MVP 이후.

### K. 데이터 영속성 (개념 수준)
- DNA 카드·6단계 묘사: DB 영구 저장. 한 번 만들어지면 재생성 불가 (운명 고정).
- 이미지: 객체 스토리지 (Supabase Storage 가정) + CDN.

## 2. 추가/구체화 필요 영역 (기획됐을 가능성 있는데 메모리에 없음)

| 영역 | 현재 상태 | 필요한 것 |
|------|-----------|-----------|
| **화면 플로우** | S2·S6 ID만 단편적으로 등장 | S1~Sn 전체 정의, 화면별 카피·레이아웃·상태 변형 |
| **VLM 파싱 스펙** | "스크린샷 업로드" 수준 | 지원 앱 우선순위(Strava/나이키런/삼성헬스), 추출 필드 표준 스키마, 프롬프트, 신뢰도 처리, 수동 보정 UX |
| **DB 스키마** | "Supabase Storage 가정" | DB 확정(Postgres?), 테이블 설계(users/characters/runs/evolutions/badges/titles/images...), ORM 선택, 마이그레이션 전략 |
| **비주얼 슬롯** | "이마/등/꼬리/색조/오라 등" 예시만 | 슬롯 확정 리스트, 속성태그→슬롯 매핑 테이블, 슬롯 충돌 시 우선순위 |
| **다양성 보너스 세부** | "+20~50" 만 정의 | 카테고리별 분류(시간대=새벽/오전/낮/저녁/밤?, 환경=트랙/로드/트레일/트레드밀?), 보너스 분배 규칙 |
| **사주→DNA 매핑 룰** | "오행+십신/일주 활용" 수준 | 오행 비율이 어떻게 archetype 후보군 좁히는지, 십신/일주가 temperament·fantasy_modifier에 어떻게 반영되는지, 동물 풀 정의 |
| **푸시 알림** | "PWA 푸시" 언급 | Web Push (Service Worker) 구체, 알림 종류·타이밍·권한 요청 흐름 |
| **디자인 시스템** | ART_STYLE_GUIDE(이미지용)만 정의 | 앱 UI 컬러·타이포·톤앤매너, 컴포넌트 라이브러리 선택(shadcn 등) |
| **정책 / 문구** | 사주 비공개 원칙만 | 개인정보 처리방침, 약관, 가입 동의 UI 카피, 사주 데이터 안내 |
| **비용 추정** | 미정 | 이미지 생성 + GPT 호출 단가 × 사용자 수 시뮬레이션, 한도 모니터링 |

## 4. 앞으로 진행 순서 (제안)

### A. 기획 마무리 (필요한 만큼만)
1. **화면 플로우 전체** (S1~Sn 정의, 와이어 수준)  ← 다음 단계
2. VLM 파싱 스펙
3. DB 스키마 (테이블 단위)
4. 비주얼 슬롯·다양성 카테고리 확정
5. 사주→DNA 매핑 룰 (간단 규칙)
6. 디자인 시스템 최소 셋
7. 정책 초안

### B. PoC (코드 진입 첫 단계, 위험 검증용 단발 스크립트)
- **사주→알 파이프라인 PoC**: lunar-typescript + DNA + 6단계 묘사 + 알 이미지를 단일 스크립트로 검증
- **VLM 파싱 PoC**: 스크린샷 1장 → JSON
- **진화 일관성 실험**: DNA + 레퍼런스 + 슬롯 입력 시 캐릭터가 같은 캐릭터로 보이는지 정성 평가. 컨셉 사활이 걸린 부분이라 코드 들어가기 전 반드시 검증.

### C. MVP 스캐폴딩
- Next.js + PWA + Supabase 세팅
- 소셜 로그인 3종 + 생년월일 fallback
- DB 스키마 적용 + 마이그레이션

### D. MVP 핵심 흐름 구현
- 가입 → 사주 계산 → DNA 생성 → 알 받기
- 업로드 → VLM 파싱 → EXP 적용 → (필요 시) 진화 트리거
- 진화 이미지 생성 + 푸시 + 모달
- 훈장 시스템 (기본 몇 개)

### E. MVP 폴리싱 + 검증
- 부정 방지 3-게이트
- 알림 시스템
- 기본 통계 화면
- 소규모 사용자 테스트
