E2 · 사이드 노트

의도

  • M1 stage·panel 레이아웃 유지. stage 중앙에 실패 메시지 + 재시도 버튼만 배치. panel은 정상 작동 — 사용자 동선 차단 최소화.
  • 모드 A(부화 실패): 알 상태 그대로. 유아 이미지 생성이 실패한 것이므로 알이 보이지 않고 실패 안내만 표시.
  • 모드 B(진화 실패): 이전 단계 캐릭터가 stage에 그대로 남아있고, 옆에 실패 안내 + 재시도 표시. 캐릭터가 사라지지 않음 — 실패해도 기존 상태 유지.
  • 재시도 버튼 누르면 E1의 대기 상태(부화 중... / 진화 중...)로 복귀. 성공 시 E1 완료 단계로 전이.
  • 재시도 횟수 제한 없음. API 비용은 서버에서 관리.
  • 카피: "다시 시도해 주세요" — README 카피 규칙(명사·라벨 중심)에서 예외적으로 안내 문구 허용. 기술 디테일("이미지 생성 API 오류") 노출 금지.

대안

  • E1 내 인라인 처리 (별도 화면 없이) — stage 상태가 명확히 다르므로 분리가 더 깔끔.
  • 자동 재시도 (사용자 액션 없이 N회 재시도) — 실패 반복 시 사용자 혼란. 수동 재시도가 기대치 관리에 유리.
  • 풀스크린 에러 모달 — M1 컨텍스트 유지 원칙과 충돌.

미정

  • 재시도 전 자동 재시도 1회 (사용자 모르게) 후 그래도 실패 시 E2 노출 — 체감 실패율 감소 효과.
  • M1 재진입 시 자동 재시도 여부 — E2 상태에서 앱을 닫고 다시 열면?
  • PWA 푸시로 "재시도 가능" 알림 여부.
