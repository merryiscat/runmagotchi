U1 · 사이드 노트

의도

  • 흐름: 업로드 → (중복 체크) → 파싱 → 확인/확정. 한 화면에서 상태 전환.
  • 중복 이미지 차단: SHA-256 해시로 동일 이미지 즉시 차단. 부정 방지 Gate A.
  • 파싱 필드 4개만: 거리·시간·페이스·날짜. 실제 런닝앱 스크린샷에서 보이는 것만.
  • 거리·시간·날짜는 수동 보정 가능. 페이스는 거리/시간에서 자동 계산 (읽기 전용).
  • 확정 후 수정·삭제 불가 — 부정 방지 원칙.

대안

  • 업로드와 결과를 별도 화면(U1→U2)으로 분리 — 한 화면이 더 빠르고 직관적.
  • 수동 보정 없이 파싱 결과 그대로 확정 — VLM 오인식 시 대처 불가.
  • 확정 전 "정말 확정?" 모달 — 경고 텍스트면 충분, 모달은 과잉.

미정

  • VLM 파싱 실패 시 UX — 전체 수동 입력 fallback? 재업로드 유도?
  • 심박수 필드 추가 여부 — 앱마다 제공 유무 다름.
  • 부정 방지 Gate B/C 검증 결과를 이 화면에서 보여줄지, 확정 후 별도 처리할지.
  • 다중 이미지 업로드 (한 번에 여러 기록) — MVP에서는 1건씩.
  • 모바일에서 카메라 직접 촬영 옵션.
  • 파싱 소요 시간 — 로딩 인디케이터 디테일.
