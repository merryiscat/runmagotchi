## 1. QA 3단계 검증 프로세스

모든 QA는 아래 3단계를 순서대로 진행한다.

### ① 코드 분석 (Static)

브라우저를 열기 전에 코드부터 읽어서 문제를 찾는다.

**체크리스트:**
- [ ] 페이지가 서버/클라이언트 컴포넌트 구분이 맞는지 (`'use client'` 필요성)
- [ ] import 경로가 올바른지 (존재하지 않는 파일 참조)
- [ ] props 타입이 일치하는지 (부모→자식 전달)
- [ ] API 엔드포인트 경로가 실제 route 파일과 일치하는지
- [ ] 환경변수 참조가 누락되지 않았는지
- [ ] Supabase 쿼리의 테이블명/컬럼명이 마이그레이션과 일치하는지
- [ ] redirect 체인에 무한 루프 가능성이 없는지
- [ ] 에러 처리가 빠진 fetch/async 호출이 없는지

**방법:**
```
1. 대상 페이지 .tsx 파일 읽기
2. import된 컴포넌트/lib 파일 읽기
3. 참조된 API route 파일 읽기
4. 관련 마이그레이션 SQL과 대조
5. TypeScript 타입 체크 실행: cd web && npx tsc --noEmit
```

### ② 브라우저 테스트 (Runtime)

Playwright MCP를 사용해 실제 브라우저에서 테스트한다.

**사전 조건:**
- dev 서버가 실행 중이어야 함 (`npm run dev`)
- 실행 중이 아니면 사용자에게 `! cd web && npm run dev` 실행을 요청

**테스트 흐름:**
```
1. browser_navigate → 대상 페이지 URL
2. browser_snapshot → 페이지 구조 확인 (렌더링 됐는지)
3. browser_console_messages → 에러/경고 수집
4. browser_click → 주요 버튼/링크 클릭
5. browser_snapshot → 클릭 후 상태 확인
6. browser_console_messages → 클릭 후 에러 확인
7. browser_network_requests → 실패한 API 호출 확인
```

**각 페이지별 테스트 시나리오:**

| 페이지 | 테스트 항목 |
|--------|-----------|
| `/login` | 로그인 폼 렌더링, 소셜 버튼 존재, 빈 제출 시 에러 |
| `/dashboard` | GNB 렌더링, 캐릭터/알 표시, 스탯 영역, 업로드 버튼 |
| `/shop` | GNB + 코인, 아이템 3종 표시, 구매 버튼 상태 |
| `/profile` | GNB, 닉네임/생년 표시, 런닝 통계 |
| `/upload` | 드롭존 표시, 파일 선택 가능, 상단바 링크 |
| `/egg-select` | 알 3개 캐러셀, 선택 버튼 |

### ③ 로그 검증 (Diagnosis)

②에서 수집한 콘솔 로그와 네트워크 요청을 분석한다.

**에러 분류:**
```
🔴 CRITICAL — 페이지 렌더링 실패, 500 에러, 미처리 예외
🟡 WARNING  — 콘솔 경고, 느린 API 응답(>3초), 404 리소스
🟢 INFO     — 정상 동작 확인, 성공 응답
```

**확인 항목:**
- 콘솔에 빨간 에러가 없는지
- 네트워크 요청 중 4xx/5xx 응답이 없는지
- React hydration mismatch 경고가 없는지
- Supabase 인증 관련 에러가 없는지
- 이미지 로드 실패(404)가 없는지

## 2. QA 리포트 형식

테스트 완료 후 아래 형식으로 리포트를 작성한다:

```markdown
## QA 리포트 — {대상 페이지/기능}

### ① 코드 분석
- ✅ 타입 체크 통과
- ✅ import 경로 정상
- 🔴 {발견된 문제}

### ② 브라우저 테스트
| 테스트 | 결과 | 비고 |
|--------|------|------|
| 페이지 로딩 | ✅ | |
| GNB 렌더링 | ✅ | |
| 버튼 클릭 | 🔴 | {에러 내용} |

### ③ 로그 검증
- 콘솔 에러: 0건
- 네트워크 실패: 0건
- 경고: {N}건 — {내용}

### 수정 필요 항목
1. 🔴 {문제} — {파일:라인} — {원인}
2. 🟡 {문제} — {파일:라인} — {원인}
```

## 3. 전체 QA (풀스캔)

대상을 지정하지 않으면 전체 페이지를 순회한다.

**순서:**
1. `npx tsc --noEmit` — 전체 타입 체크
2. 각 페이지 코드 분석 (login → onboarding → egg-select → dashboard → shop → profile → upload)
3. 브라우저로 로그인 → 각 페이지 이동 → 스냅샷 + 클릭 + 로그 수집
4. 종합 리포트 작성

## 4. 테스트 계정

- **테스트 전용:** `test@runmagotchi.com`
- 다른 계정 데이터는 절대 수정/삭제하지 않는다
- 테스트 중 생성한 데이터는 test 계정에서만 작업

---

## 5. 주의사항

- dev 서버가 꺼져있으면 브라우저 테스트를 건너뛰고 코드 분석만 수행
- Playwright snapshot이 빈 화면이면 → 서버 사이드 에러 가능성, 터미널 로그 확인 요청
- 테스트 중 데이터 변경(구매, 업로드 등)은 test 계정에서만 수행
- 스크린샷 촬영은 문제 발견 시에만 (불필요한 스크린샷 자제)
